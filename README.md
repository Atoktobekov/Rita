# Daily To-Do · 0.5.0

Приложение для ежедневного планирования на **Android и iOS**. Автор идеи и проекта — **Ади**.

## Возможности

- Выполнение нажатием на всю карточку; индикатор справа. Удержание открывает редактирование и удаление с отменой.
- Плавное перемещение выполненных задач под незавершённые; свайпы между четырьмя вкладками и равные секции нижней навигации.
- Карточки на сегодня, завтра и произвольную дату; дату можно изменить в форме задачи.
- Простой список без категорий, с фильтром по выполнению и компактным прогрессом дня.
- Копирование всех незавершённых задач выбранного прошедшего или текущего дня на завтра с отменой; исходные задачи сохраняют историю выполнения.
- Экспорт и импорт JSON-копий задач с предпросмотром и сохранением предыдущей версии.
- Изоляция повреждённых записей без удаления исходных данных; сохранение текста редактора при ошибке записи.
- Карточки и действия доступны для экранного диктора; зоны нажатия от 48 пикселей, проверка шрифта 200% и поддержка отключения анимации перемещения.
- Редактируемая история прошедших дней, автоматическое обновление после полуночи.
- Статистика, интерактивный график за последние шесть дней, серии и 13 обычных достижений плюс одно секретное. Нажатие на день графика открывает редактируемую карточку дня.
- Ежедневное локальное вечернее напоминание с выбором времени и отключением.
- Четыре дизайна со своими светлыми и тёмными палитрами, сохранением выбора и поддержкой системного режима.
- Локальное хранение без регистрации и сервера. Данные версии 0.1 сохраняются.

## Напоминание

Напоминание настраивается через «Статистика» → шестерёнка «Настройки» → «Вечернее напоминание». По умолчанию напоминание выключено, время — **21:30**. Рекомендуемый интервал — 21:00–22:00, но можно выбрать любое удобное время. Разрешение запрашивается только при включении. При отказе приложение объяснит, как разрешить уведомления в настройках телефона.

Напоминание приходит ежедневно по местному времени: «Как прошёл твой день? Отметь выполненные задачи и составь план на завтра». Выбор времени сохраняется после перезапуска. Изменение времени заменяет прежнее расписание, отключение отменяет его. При возвращении в приложение расписание обновляется с учётом текущего часового пояса. После поездки откройте приложение, чтобы применился новый пояс.

Android использует неточный будильник, поэтому отдельное разрешение на точные сигналы не требуется; энергосбережение может задержать доставку. Добавлены разрешение уведомлений, восстановление расписания после перезагрузки и обновления приложения, отдельная монохромная иконка. На iOS разрешения запрашиваются через системный диалог; настроен показ в открытом приложении. Web и Windows остаются дополнительными оболочками, напоминания там недоступны.

## Дизайн из Figma

Исходник: `Четыре дизайна Daily To-Do/src/App.tsx` и `src/index.css`. Доступны четыре дизайна:

- **Уют** — тёплый минимализм, выбран по умолчанию; бумажные оттенки и персиковые акценты.
- **Фокус** — строгий современный; прямые формы и лаймовые акценты, графитово-зелёная тёмная палитра.
- **Искра** — мягкий игровой; округлые карточки, цветные панели и лавандовые акценты, сливовая тёмная палитра.
- **Лист** — тихая редакция; заголовки с засечками, разделители и голубые акценты, сине-чёрная тёмная палитра.

Выбор: «Статистика» → шестерёнка «Настройки» → «Дизайн приложения». Дизайн сохраняется в `settings_v1` под ключом `design_theme` (`warm`, `strict`, `play`, `editorial`) независимо от светлого/тёмного режима. Отсутствующее или неизвестное значение открывает «Уют». Шрифты Golos Text и Literata поставляются локально в `assets/fonts/` с лицензиями OFL; подключение к сети не требуется.

Нажатие на дату открывает выбор «Сегодня», «Завтра» и календарь. Нажатие на любую часть карточки переключает выполнение. Удержание открывает действия «Редактировать» и «Удалить»; удаление можно отменить. Нажатие на заголовок «ЗАДАЧИ» открывает фильтры. Архив раскрывается на месте и использует те же карточки, жесты и анимацию. День из диаграммы открывается снизу: задачи можно выполнять, редактировать, удалять и добавлять.

Декоративная рамка телефона и демонстрационная статусная строка веб-превью заменены системными безопасными зонами устройства. В настройках вкладки «Статистика» доступны светлая, тёмная и системная темы. Выбор сохраняется в `settings_v1` под ключом `theme_mode`; системная тема следует настройке устройства. Демо-данные экспорта используются только в тестах визуальной проверки, база пользователя ими не заполняется.

## Архитектура

Проект разделён по Clean Architecture. Domain не зависит от Flutter, Hive и плагинов. Зависимости передаются через конструкторы; связывание реализаций выполняется в `main.dart`.

```text
lib/
  main.dart                        Инициализация и сборка зависимостей
  app.dart                         Тема и локализация приложения
  core/calendar.dart               Локальные календарные даты
  domain/
    entities/                      Task, ReminderSettings
    repositories/                  Контракты хранения и планировщика
    usecases/                      Управление задачами, напоминанием, статистика
  data/
    models/                        Сериализация задач
    repositories/                  Реализации хранения в Hive
    services/                      Нативный планировщик уведомлений
  presentation/
    controllers/                   Состояние экранов и вызовы сценариев
    pages/                         План дня, история, прогресс, напоминание
    widgets/                       Форма задачи и календарь
    theme/                         Палитра
```

Задачи хранятся единым снимком в `tasks_v2` (ключ `state`, версия 2): исправные записи, изолированные повреждённые записи и предыдущая версия перед импортом. Из `tasks_v1` данные автоматически копируются при первом запуске новой версии; исходный box сохраняется без изменений. После переноса приложение читает `tasks_v2`. Каждая запись задачи содержит `id`, `title`, `day`, `category`, `done`. Поле `category` сохранено только для совместимости старых данных и JSON-копий; в интерфейсе категорий нет. Настройки темы и напоминания остаются отдельно в `settings_v1`. Дата задачи — локальная календарная строка `YYYY-MM-DD`, без перевода в UTC. Архив формируется из прошлых дат без перемещения данных. Статистика не учитывает будущие задачи. Достижения вычисляются по текущим данным, поэтому удаление или изменение выполненных задач может снова их заблокировать.

Изменения задач публикуются в интерфейсе после успешной записи. Импорт, массовое копирование и восстановление записываются одной операцией Hive: при ошибке не публикуется частичный результат. Это требует перезаписи снимка коллекции при изменениях; для локального планировщика выбран приоритет целостности данных. Повреждённые отдельные записи сохраняются в секции `rejected` вместе с исходным значением и причиной ошибки; их количество видно на главном экране и в копиях задач. Если повреждён весь контейнер или файл Hive, приложение показывает ошибку открытия и не заменяет его пустыми данными. Если сохранение настроек уведомления завершается ошибкой, приложение пытается восстановить прежнее расписание и показывает ошибку.

## Копии и продолжение плана

Кнопка «Копии задач» в правом верхнем углу вкладки «Архив» открывает экспорт, импорт и восстановление. JSON содержит задачи всех дат; настройки темы, напоминания и изолированные повреждённые записи остаются на устройстве. В браузере экспорт запускает скачивание; на Android, iOS и настольных платформах используется системный файловый диалог.

Импорт принимает формат `daily-todo-tasks`, версию 1, не более 10 МБ и 20 000 задач. До записи проверяются поля, уникальность идентификаторов и календарные даты (1900–2200). После выбора файла показываются дата копии, число задач и диапазон дат. Замена требует подтверждения, в том числе для пустой копии. Предыдущая версия сохраняется атомарно с импортом. Кнопка восстановления меняет текущую и предыдущую версии местами; повторное восстановление отменяет его.

Кнопка «Скопировать незавершённые на завтра» расположена под списком и полем добавления задач. Она создаёт независимые невыполненные копии с новыми идентификаторами независимо от фильтров. Оригиналы остаются на исходной дате и учитываются в её проценте выполнения. Каждое нажатие создаёт новую партию копий. Отмена удаляет только копии этой операции и отказывается от удаления, если какая-либо копия уже изменена или удалена. Ошибка записи не публикует частичный результат. Кнопка «Будущие планы» показывает даты с задачами по порядку.

Редактор закрывается только после успешного сохранения. При ошибке название и дата остаются в форме для повторной попытки. Во время записи повторное сохранение и закрытие формы блокируются.

## Достижения 0.5.0

Пороговые достижения: «Первоход» — 1, «Червонец» — 10, «Четвертак» — 25, «Пять по десять» — 50, «Трудоголик» — 100, «Бонаква» — 250 выполненных задач.

«Ты у меня третий» — 3 дня подряд от 50%; «Эйс» — первый непустой день со 100%; «Жигули» и «Эпштейн» — суммарно 7 и 14 дней от 50%. «Бешке бир» и «Тайная вечеря» — соответственно 5 и 13 дней подряд со 100%. Для серий используются календарные дни без пропусков; учитывается лучшая серия за всю сохранённую историю. Пустой день не считается днём со 100%.

NNN — 30 завершённых календарных дней подряд без выполненных задач, включая пустые дни, но не раньше первой задачи в сохранённой истории. Текущий незавершённый день не засчитывается.

Секретный «Дрочер» появляется в списке и счётчике только после выполнения задачи со словами «дрочить», «подрочить», «дрочка», «мастурбация», «онанизм» или поддерживаемыми формами этих слов. Проверяются целые русские слова без учёта регистра. Будущие задачи не учитываются ни в статистике, ни в достижениях. Как и прежде, достижения вычисляются по текущим данным: редактирование и удаление истории могут изменить результат.

## Запуск и проверка

Требуются **Flutter 3.50.0+**, **Dart 3.14.0+**. Android-сборка использует **Gradle 9.3.1**, **Android Gradle Plugin 9.1.1**, **Kotlin 2.4.10** и **Android NDK 29.0.14206865**.

```sh
flutter pub get
flutter run -d <device-id>
flutter analyze
flutter test
flutter build apk --debug
```

Тесты проверяют чтение данных 0.1, реальное повторное открытие Hive, перенос задачи между датами, ошибки записи, статистику, смену дня, отказ в разрешении уведомлений, изменение и отмену расписания, выбор произвольной даты и узкий экран. Нативная доставка уведомлений требует проверки на устройствах; тесты сценариев используют подставной планировщик.

Для визуальной проверки экранов:

```sh
flutter test test/preview_test.dart --dart-define=VISUAL_REVIEW=true
```

Снимки создаются в `build/qa/theme-{warm|strict|play|editorial}-{light|dark}-{day|archive|statistics|awards|menu}.png`; отдельно сохраняется экран выбора темы. Тесты проверяют восемь сочетаний дизайна и режима, узкий экран со шрифтом 200%, сохранение в Hive и ошибки записи.

Для iOS нужны macOS, Xcode и CocoaPods; команда `flutter build ios --no-codesign`. Для установки на iPhone задайте Apple Development Team. Android release пока использует debug-подпись — для публикации потребуется собственный ключ.
