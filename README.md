# Daily To-Do · 0.2

Приложение для ежедневного планирования на **Android и iOS**. Автор идеи и проекта — **Ади**.

## Возможности

- Создание, редактирование, выполнение и удаление задач с отменой.
- Карточки на сегодня, завтра и произвольную дату; дату можно изменить в форме задачи.
- Категории: личное, работа, здоровье, развитие; метки на карточках и совместные фильтры по категории и выполнению.
- Перенос всех незавершённых задач выбранного прошедшего или текущего дня на завтра с отменой; обзор будущих планов.
- Экспорт и импорт JSON-копий задач с предпросмотром и сохранением предыдущей версии.
- Изоляция повреждённых записей без удаления исходных данных; сохранение текста редактора при ошибке записи.
- Зоны нажатия от 48 пикселей у галочек и удаления, озвучивание названий задач, проверка шрифта 200%.
- Редактируемая история прошедших дней, автоматическое обновление после полуночи.
- Статистика, график за последние шесть дней, серия дней и одиннадцать достижений.
- Ежедневное локальное вечернее напоминание с выбором времени и отключением.
- Простой русский интерфейс: белый `#FFFFFF`, персиковый `#FFCF94`, контрастный тёмный текст.
- Локальное хранение без регистрации и сервера. Данные версии 0.1 сохраняются.

## Напоминание

Напоминание настраивается прямо в карточке дня. Нажмите колокольчик, чтобы открыть подробные настройки. По умолчанию напоминание выключено, время — **21:30**. Рекомендуемый интервал — 21:00–22:00, но можно выбрать любое удобное время. Разрешение запрашивается только при включении. При отказе приложение объяснит, как разрешить уведомления в настройках телефона.

Напоминание приходит ежедневно по местному времени: «Как прошёл твой день? Отметь выполненные задачи и составь план на завтра». Выбор времени сохраняется после перезапуска. Изменение времени заменяет прежнее расписание, отключение отменяет его. При возвращении в приложение расписание обновляется с учётом текущего часового пояса. После поездки откройте приложение, чтобы применился новый пояс.

Android использует неточный будильник, поэтому отдельное разрешение на точные сигналы не требуется; энергосбережение может задержать доставку. Добавлены разрешение уведомлений, восстановление расписания после перезагрузки и обновления приложения, отдельная монохромная иконка. На iOS разрешения запрашиваются через системный диалог; настроен показ в открытом приложении. Web и Windows остаются дополнительными оболочками, напоминания там недоступны.

## Дизайн из Figma

Исходник: `Design Daily To-Do App Ver2/src/App.tsx` и `src/index.css`. Перенесены четыре вкладки: «Сегодня», «Архив», «Статистика», «Ачивки», круговые индикаторы, карточки, быстрое добавление, встроенное напоминание и SVG-пути иконок. Google Sans поставляется локально в `assets/fonts/` вместе с лицензией OFL.

Нажатие на дату открывает выбор «Сегодня», «Завтра» и календарь. Нажатие на текст задачи открывает редактор с категорией и датой; удаление можно отменить. Нажатие на заголовок «ЗАДАЧИ» открывает фильтры. Архив раскрывается на месте, позволяет отмечать задачи и открывать день для дополнения.

Декоративная рамка телефона и демонстрационная статусная строка веб-превью заменены системными безопасными зонами устройства. На узких экранах время напоминания переносится под подпись. Демо-данные экспорта используются только в тестах визуальной проверки, база пользователя ими не заполняется.

## Архитектура

Проект разделён по Clean Architecture. Domain не зависит от Flutter, Hive и плагинов. Зависимости передаются через конструкторы; связывание реализаций выполняется в `main.dart`.

```text
lib/
  main.dart                        Инициализация и сборка зависимостей
  app.dart                         Тема и локализация приложения
  core/calendar.dart               Локальные календарные даты
  domain/
    entities/                      Task, ReminderSettings
    repositories/                  Контракты хранения и планировщика
    usecases/                      Управление задачами, напоминанием, статистика
  data/
    models/                        Сериализация задач
    repositories/                  Реализации хранения в Hive
    services/                      Нативный планировщик уведомлений
  presentation/
    controllers/                   Состояние экранов и вызовы сценариев
    pages/                         План дня, история, прогресс, напоминание
    widgets/                       Форма задачи и календарь
    theme/                         Палитра
```

Задачи хранятся единым снимком в `tasks_v2` (ключ `state`, версия 2): исправные записи, изолированные повреждённые записи и предыдущая версия перед импортом. Из `tasks_v1` данные автоматически копируются при первом запуске новой версии; исходный box сохраняется без изменений. После переноса приложение читает `tasks_v2`. Каждая запись задачи содержит `id`, `title`, `day`, `category`, `done`. Настройки напоминания остаются отдельно в `settings_v1`. Дата задачи — локальная календарная строка `YYYY-MM-DD`, без перевода в UTC. Архив формируется из прошлых дат без перемещения данных. Статистика не учитывает будущие задачи. Достижения вычисляются по текущим данным, поэтому удаление или изменение выполненных задач может снова их заблокировать.

Изменения задач публикуются в интерфейсе после успешной записи. Импорт, массовый перенос и восстановление записываются одной операцией Hive: при ошибке не публикуется частичный результат. Это требует перезаписи снимка коллекции при изменениях; для локального планировщика выбран приоритет целостности данных. Повреждённые отдельные записи сохраняются в секции `rejected` вместе с исходным значением и причиной ошибки; их количество видно на главном экране и в копиях задач. Если повреждён весь контейнер или файл Hive, приложение показывает ошибку открытия и не заменяет его пустыми данными. Если сохранение настроек уведомления завершается ошибкой, приложение пытается восстановить прежнее расписание и показывает ошибку.

## Копии и продолжение плана

Кнопка «Копии задач» рядом с заголовком дня открывает экспорт, импорт и восстановление. JSON содержит задачи всех дат и категорий; настройки напоминания и изолированные повреждённые записи остаются на устройстве. В браузере экспорт запускает скачивание; на Android, iOS и настольных платформах используется системный файловый диалог.

Импорт принимает формат `daily-todo-tasks`, версию 1, не более 10 МБ и 20 000 задач. До записи проверяются поля, уникальность идентификаторов и календарные даты (1900–2200). После выбора файла показываются дата копии, число задач и диапазон дат. Замена требует подтверждения, в том числе для пустой копии. Предыдущая версия сохраняется атомарно с импортом. Кнопка восстановления меняет текущую и предыдущую версии местами; повторное восстановление отменяет его.

«Все незавершённые на завтра» переносит задачи выбранного дня независимо от фильтров, сохраняя их идентификаторы. Выполненные задачи остаются на своей дате. Отмена доступна в уведомлении; если перенесённые задачи уже изменены, она не перезаписывает новые изменения. Кнопка «Будущие планы» показывает даты с задачами по порядку.

Редактор закрывается только после успешного сохранения. При ошибке название, категория и дата остаются в форме для повторной попытки. Во время записи повторное сохранение и закрытие формы блокируются.

## Запуск и проверка

Требуются **Flutter 3.50.0+**, **Dart 3.14.0+**. Android-сборка использует **Gradle 9.3.1**, **Android Gradle Plugin 9.1.1**, **Kotlin 2.4.10** и **Android NDK 29.0.14206865**.

```sh
flutter pub get
flutter run -d <device-id>
flutter analyze
flutter test
flutter build apk --debug
```

Тесты проверяют чтение данных 0.1, реальное повторное открытие Hive, перенос задачи между датами, ошибки записи, статистику, смену дня, отказ в разрешении уведомлений, изменение и отмену расписания, выбор произвольной даты и узкий экран. Нативная доставка уведомлений требует проверки на устройствах; тесты сценариев используют подставной планировщик.

Для визуальной проверки экранов:

```sh
flutter test test/preview_test.dart --dart-define=VISUAL_REVIEW=true
```

Снимки создаются в `build/qa/`.

Для iOS нужны macOS, Xcode и CocoaPods; команда `flutter build ios --no-codesign`. Для установки на iPhone задайте Apple Development Team. Android release пока использует debug-подпись — для публикации потребуется собственный ключ.
